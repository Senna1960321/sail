## sail 0.25.0 (pre-release)

### Breaking changes

- **`quic.window_budget`, `quic.free_memory_floor` and
  `quic.anon_memory_max` are now `memory.transfer_budget`,
  `memory.free_memory_floor` and `memory.anon_memory_max`**: the budget
  covers accepted connections' send buffers as well as the QUIC windows.
  The old keys are not read.
- **A connection's closed record is never lost, and interim records
  carry totals** (sail#24): with `Options::connection_records_lossless`,
  every closed record is kept for the reader. Records past the cap are
  no longer folded into summaries (`Record::Folded` and `RecordSummary`
  are gone, and `RecordStream::next` gives the record itself). While
  `cap` closed records wait for the reader, new connections are refused,
  counted by `RecordStream::refused`, until it takes one. Records carry
  the bytes since the connection started, `up_total` and `down_total`;
  `up`, `down` and `since` are gone, from the event, its JSON (`since_ms`)
  and the bindings. Interim records of a timed pass are dropped while the
  queue is full, counted by `RecordStream::dropped`.
  `Instance::report_connections` (`POST /connections/report`) now
  records every open connection, idle ones too, and a lossless sink keeps
  all of them.

### Embedding

- **A closed record tells how the connection was used** (sail#24):
  `outcome` is `Ok`, `DialFailed`, `Blocked` or `Rejected`. A connection
  that never relayed now has a closed record too: a dial that failed, a
  reject or drop rule, a user refused at its limits. Records also carry
  `local`, the address the client connected to, and `outbound`, the tag
  the rules chose.

- **Limits a host sets for a user stay through a reload** (sail#26):
  `set_user_limits` and the management API's `PUT /users/{name}/limits`
  set an override over `user_limits`, which a reload keeps unless it
  changes what the configuration sets for that user. Then the override is
  dropped, and `ReloadReport::user_limits_dropped` (`user_limits_dropped`
  in its JSON) names the user. `restore_user_limits` drops it. A reload
  used to put back the configuration's limits for every user.

- **A host outbound may keep a `Via` for later hops**: `Via` is `Clone`,
  so a host can dial deferred UDP next hops after `datagrams` returned.
  A retained `Via` holds the instance's outbounds and DNS client weakly;
  once the instance stops, its dials fail.

- **Multiplex reuse and padding counters** (#57): `sail::muxcore::stats()`
  adds `sessions_created`, `streams_opened`, `streams_reused` and, for
  AnyTLS, `padding_received_bytes`, process-wide lifetime counters.
- **A host attaches and detaches packet capture on a running instance**
  (#54): with `Options::dynamic_tun(true)` (feature `inbound-tun`),
  `Instance::prepare_tun_packets`, or `prepare_tun_device` on Unix,
  reserves a TUN inbound, `PreparedTun::commit` publishes it, and
  `detach_tun` ends its flows, NAT and DNS work, while listeners and
  shared carriers stay up. `tun_state` tells where it is. A stop drains
  the attachment within `stop_within`, the same bound as the instance's
  tasks. With it on, a network state the host pushes is the host's alone:
  sail's own watchers no longer reset connections after it, and the
  device's exact name is never chosen to go out of. A pushed state that
  names no interface leaves the way out to detection. Off, as by
  default, nothing changes.

### Configuration

- **`user_limits.<name>.total_mbps`, one rate up and down together**
  (sail#26): both directions draw from it, by every connection of the
  user, alongside `up_mbps` and `down_mbps` where those are set. It
  changes live through `set_user_limits`, like the others.

- **An outbound's `tls.record_fragment` and `tls.fragment` cut its
  ClientHello** (sail#61), as in sing-box 1.12: into TLS records sent in
  one write, into TCP segments `tls.fragment_fallback_delay` apart (500ms
  unset), or both, each record a segment. The cut falls inside the server
  name, never before its first byte: sing-box's may, leaving the whole
  name in the second piece. The wait between segments is fixed, where
  sing-box waits for the segment's ACK. Off by default; refused over QUIC (Hysteria2, TUIC), under
  ShadowTLS and for DNS servers. The route options `tls_fragment` and
  `tls_record_fragment` may now be set together, as sing-box allows.

- **Sail/1, sail's own protocol, wire v1** (sail#60), behind the
  `inbound-sail` and `outbound-sail` features: `"type": "sail"`. Streams
  share one TLS connection, authenticated once by a 32-byte token, with
  per-stream windows and half-close; a client sends at once and the
  server answers each stream's status in-band. Streams that open while a
  session is being dialled wait for it, up to 8 a session, rather than
  each dialling its own; run a Sail/1 server with BBR
  (`--set relay.tcp_congestion=bbr` or
  `net.ipv4.tcp_congestion_control = bbr` on Linux) so packet loss does
  not collapse a shared CUBIC window. What does not open with a
  valid prelude goes to `fallback`, with the bytes read of it. UDP goes
  over the same sessions' streams, as sing-box's UDP over TCP version 2,
  every packet naming its address. Unlike every other multiplexed
  protocol, a Sail/1 stream nothing reads is not reset after
  `mux.stall_timeout`: it is kept, as a paused TCP connection is, its
  window charged to `memory.transfer_budget`, and reset only where the
  budget has no room for it. A Sail/1 session whose peer leaves a ping
  unanswered for 30 s ends. The format may still change before it is
  declared stable.

### Embedding

- **A host submits a user's streams and datagrams with no listener**
  (sail#25): `Instance::sessions(tag)` gives the `Sessions` of the
  inbound `tag` for a host that takes its users' traffic off a link of
  its own. Each session is routed by the rules for that inbound and user,
  dialled with the outbound's bind address, held to the user's limits and
  rates, and recorded, as a host inbound's is, and the host's stream is
  relayed to the outbound's with one copy. `NewSession::source` and
  `local` give a session its client's addresses, and `SessionInfo::local`
  tells a host outbound the address the client connected to.
- **A host's own admission** (sail#23): `Options::admit` checks each
  session before it is routed, `Options::admit_source` each connection
  and QUIC handshake by its addresses before its handshake, after sail's
  own admission; what they reject is closed and never routed. A session
  `admit` rejects has one closed record, `Rejected`, ended
  `Closed(Host)`, with the check's `reason` (`closed_by` `host` and
  `reason` in the JSON records). `Instance::admission()` and `GET /admission` count the
  rejections by reason (`host_refused`) and the checks that panicked
  (`host_panics`), each of which rejects its connection.
- **`dial_tcp` and `dial_udp` return the outbound's own stream and
  datagrams**, with no relay or copy between, usable from any executor;
  sail's idle and stall timeouts no longer apply to them: their timeouts
  are the host's.
- **`sail::muxcore`, sail's stream multiplexer for a host's own links**
  (sail#27, feature `muxcore`): yamux sessions over any `AsyncRead +
  AsyncWrite`, `Session::client` and `Session::server`, with async `open`
  and `accept`, and a `Config` for the window and stall timeout. It is
  the one sail's yamux runs on, with what sail#21 and sail#22 fixed, and
  follows `sail::embed`'s rules: it only grows, and a break is listed
  here.

### Fixed

- **Sequential `prefer_h3` retries leave HTTP/2 a complete attempt** (#47):
  the selected HTTP/3 probe uses half the member's attempt timeout, including
  a cold QUIC handshake, then yields a fresh attempt to HTTP/2. On a lossy
  network this shorter handshake allowance can demote HTTP/3 to HTTP/2 for
  its ten-minute cooldown more readily. A stale HTTP/2 probe also reaches
  the sequential retry while a concurrent HTTP/3 probe is still pending.

- **Sequential DoH retries keep the replacement's full attempt** (#43):
  a retained HTTP/1.1 or HTTP/2 connection's short probe deadline no longer
  consumes the replacement's budget. DoT and HTTP/2 share the freshness
  rule: a busy pipeline that stops answering is probed again, so steady
  queries cannot keep a dead connection alive indefinitely. A healthy retained
  connection taking more than half the attempt timeout to answer can still
  be retired, costing another TLS handshake.

- **TLS and QUIC initialize native crypto state safely**
  ([btls#2](https://github.com/peakpassvpn/btls/pull/2),
  [quinn-btls#2](https://github.com/peakpassvpn/quinn-btls/pull/2)):
  random-number generation keeps its stack fallback when thread-local
  setup fails, without cleaning up the same state twice. AES key
  schedules are fully initialized, including QUIC header keys, and HMAC
  setup checks allocation and releases its context on error.
- **Shrinking a QUIC send window keeps budget for retained data**
  (sail#52, [quinn#2](https://github.com/peakpassvpn/quinn/pull/2)):
  Hysteria2 and TUIC keep their granted send-buffer growth charged until
  ACKs or reset release the retained storage, including allocations kept
  by partial or selective ACKs. Another connection can no longer reuse
  that allowance while the data remains buffered.
- **QUIC receive errors reach the endpoint, and reset streams and path
  migration keep their limits** (sail#1): the Quinn fork now returns UDP
  receive errors other than `WouldBlock` instead of retrying them in a
  tight loop. Stopping a stream after its reset no longer gives
  connection-level flow-control credit twice, including when credit is
  lent from the transfer budget. MTU probes wait for path validation,
  so they cannot bypass the new path's anti-amplification limit during
  migration.
- **Dropping a connection's closed record frees its `record_context`
  slot at once** (sail#76): a session whose final record had been queued
  still held a copy of its `RecordContext` until the session and its
  counter finished dropping, so a host that read and dropped the record
  could still hit `record_context_capacity` on the next connection. The
  binding is now moved into the closed record's envelope as its sole
  owner.
- **A TUN's TCP segments fit the client's MSS with their options**: the
  stack took the MSS a client announced as the payload of its segments,
  though the timestamps and SACK blocks they carry come on top (RFC 6691),
  so a client announcing 1460 got packets of up to 1520 bytes over a TUN
  whose MTU is larger, as a phone's 9000. Segments now carry the MSS less
  those options: 1448 with timestamps, 1420 with SACK.
- **Rule-set rules match as sing-box's and Mihomo's** (sail#31): a
  sing-box rule-set rule with no conditions (`{}`, or only `invert`), in
  the source or the binary format, is refused with `missing conditions`
  instead of matching everything. A Clash, Surge or MRS list with no
  entry taken matches nothing. An IPv4-mapped range in a binary rule-set
  (`::ffff:0:0/96`) stays IPv6, so it no longer matches every IPv4
  address.
- **A DNS cache clear that failed to write is tried again** (sail#58):
  with `store_dns`, the DNS answers on disk are not read until a clear
  commits; a clear whose commit failed was never tried again, so they
  stayed unread for the rest of the run. It is now retried each second,
  with one warning until it succeeds.
- **A UDP session ends when its send fails**: a send error ended the
  session's uplink but left the session in place until its idle
  timeout, so the source's later packets were dropped and the session
  kept one of `inbound.max_connections`; while closing the failed sender
  did not return, it kept that place for good. The session now ends
  with the error, without closing the failed sender, and the source's
  next packet opens a new one. A send error on an older session of the
  same source does not end its replacement.
- **Concurrent DNS-over-TLS queries share a connection** (sail#8):
  replies are matched by message ID and may arrive out of order. Each
  server admits up to 64 queries at once and has at most 4 live
  connections, including older connections still finishing queries;
  further queries wait within their DNS timeout. A cancelled query's
  late reply cannot answer another query.
- **A DNS answer arriving after the cache was cleared is not kept**
  (#46): a cache clear or network change revokes the writes of queries and
  background refreshes already under way, so a late answer, from the
  network before, no longer refills the cache.
- **Health checks read a TCP probe's whole response** (#49): a `PONG`
  that arrives in more than one read no longer fails the check.
- **A cancelled admission wait gives its place back, and DNS answers
  keep their sessions** (#53): a session that stopped waiting for a user's
  connection place no longer holds a waiting slot. A UDP session that
  carries hijacked DNS stays until its queries are answered and the
  answers taken, rather than ending at the first reply. Under a sequential
  server, DNS-over-TLS queries that time out on a kept connection share
  one replacement, which keeps its whole attempt budget; queries joining a
  connection that has just opened, or is answering, keep the normal DNS
  timeout, and a busy connection that falls silent is still given up.
- **`inbound.tcp_send_buffer` is the size asked for** (sail#10): Linux
  stops a plain request at `net.core.wmem_max`, 208 KiB by default, so
  the router profile's 256 KiB was 208 on most kernels. sail now asks past
  the limit, as it does for `inbound.tcp_receive_buffer`, where it has
  CAP_NET_ADMIN, as on a router.
- **A host inbound's UDP session is no longer refused for its user's
  `max_tcp_connections`**: the check before routing took every session
  of a host inbound's connection for TCP.
- **Shrinking a TCP send buffer keeps allowance for data still queued**
  (sail#10): lowering `SO_SNDBUF` does not release that memory. Its
  excess allowance now stays in `memory.transfer_budget` until a write
  observes drainage, or the connection closes; if the queue cannot be
  queried, it stays reserved until close. Growth reads back the actual
  size and refunds only unused new allowance. Failed readback keeps the
  requested growth charged. An idle or canceled writer may retain
  drained allowance until its next write or close. Close returns Sail's
  reservation, not necessarily all of TCP's queued memory.
- **An idle connection takes what it took before 0.24.0:** in 0.24.0
  each routed connection's number kept room for a copy of its session,
  about a kilobyte, which only a session told to a host needs. On a
  server an idle Shadowsocks 2022 connection took 1.16 times what it took
  before and a Trojan one 1.09 times; now 0.95 and 1.01.
- **Clients that stop reading no longer stall the other streams on
  their Hysteria2 or TUIC connection** (`quic.credit_on_receipt`,
  sail#18): a connection gave its peer credit back only as stream data
  was read, so two or three streams nobody read, such as paused
  downloads, used up its window and left the others none. sing-box
  (quic-go) does the same. The credit is now given as data arrives,
  lent out of `memory.transfer_budget` until the stream reads it, so a
  stalled stream holds its own window and no more; where the budget is
  spent, credit comes back on read as before. A stream left unread for
  `mux.stall_timeout` (60 s), which QUIC streams now take as the
  multiplexers do, is reset, and its loan repaid. On a router, 4 LAN
  downloads beside 20 clients that stopped reading went from nothing to
  2.4–3.7 Gbit/s; sing-box's still get nothing (measured, sail#18).
- **A TUIC client logs why its connection closed** (at debug, the
  application's code or the transport error and its frame), as a
  Hysteria2 client already did; it dropped a closed connection silently.
- **A yamux or amux stream dropped before the peer finished it is reset
  alone** (sail#21): its session had taken no new streams since, and
  closed after its last, so that every cancelled request over a
  long-lived yamux connection between two nodes cost a new connection.
  What the peer sent the stream before it heard is now dropped as it
  comes, and the session goes on. smux and AnyTLS, which cannot reset one
  stream, retire their session as before. A stream dropped before the
  peer's FIN is reset, where Go's yamux `Close` sends a FIN.
- **A yamux client waits while 256 of its streams are unacknowledged**
  (sail#22), as hashicorp/yamux's client and rust-yamux do: it opened
  every stream at once, and hashicorp/yamux resets those past its accept
  backlog of 256, so that of 500 streams opened at once some failed. All
  500 now complete against it, which CI checks on every change, both
  ways (tested).
- **A file written within a few milliseconds of being read is read again**
  (sail#28): a configuration file, a certificate or a local rule-set
  written in the same tick of the file system's clock as the write before
  it was read, at the same length, kept its size and time of
  modification, and the write was never applied until the next change.
  A file modified less than 2 s before it is read is now told by its
  content as well, as git treats a racily clean file, and one that holds
  the same is not reloaded.

### Diagnostics

- **Opt-in internal diagnostics for embedding hosts** (#55): with the
  `internal-diagnostics` feature, `Instance::internal_diagnostics()`
  gives the running dispatcher's admission refusals, wait timeouts and
  abandoned waits. With `internal-udp-target-diagnostics`, a host that
  sets `Options::internal_udp_target_policy` to one IPv4 endpoint also
  gets the newest 16 observations of UDP traffic to it, through NAT,
  routing, the AnyTLS carrier and UoT writes, with no addresses, names or
  payloads. Both features are off by default and change nothing when off.
- **Transport diagnostics** (sail#69): with `internal-diagnostics`,
  `Instance::internal_diagnostics_with_transport()` adds a `transport`
  child to the same snapshot. It holds:
  - the running TUN stack's counters;
  - its busiest TCP flow over the last read (round trip, bytes in flight
    and held, the client's window);
  - the packet bridge's queue depths and waits on a full queue;
  - the relays' waits on their writers and readers.
  docs/internal-transport-diagnostics.md lists the fields.

### Dependencies

- **Tokio 1.53.3 or later, rustix 1.1.6** (#56): Sail now requires
  Tokio 1.53.3, which fixes the unsound `AsyncFd` constructors of
  RUSTSEC-2026-0386, and locks rustix 1.1.6 for RUSTSEC-2026-0486. An
  embedder whose lock holds an older Tokio 1.x moves to it. The
  dependency gate now fails on unsound and yanked advisories and on an
  unreadable registry index.
- **chrono is gone** (#56): RUSTSEC-2026-0543 marks it unmaintained.
  RFC 3339 times, in the Clash API and the management API, and
  `user_limits.<name>.expire_at`, are written and read with `time`,
  already in the graph, in the same shapes as before. `expire_at` beyond
  the year 9999 is refused. `UserLimits::expire_at()` returns a
  `SystemTime`.
- **smoltcp 0.14 in netstack tests** (#75): the interop tests move from
  smoltcp 0.12 to 0.14, which brings heapless 0.9.4 and clears
  RUSTSEC-2026-0574 to -0582. smoltcp is a development dependency only;
  no release build links it.

### Default changes

- **A router's QUIC endpoint takes 8 datagrams per receive, not 32**
  (`quic.udp_receive_batch`, sail#10): the room it keeps for them falls
  from about 3 MB to 0.75. In a 64 MiB cgroup downloads peaked 2–3 MiB
  lower and no cell was slower, on the LAN at 0 and 8 ms and at 150 and
  300 ms. Zero keeps quinn's 32, as other profiles do.
- **A router's LAN downloads grow their send buffer out of one memory
  budget** (`inbound.tcp_send_buffer_max`, sail#10): an accepted TCP
  connection starts at `inbound.tcp_send_buffer` (256 KiB) and doubles,
  up to 2 MiB, while that buffer rather than the network or the client
  holds the download back, out of the budget Hysteria2's and TUIC's
  windows grow from. While writes are polled, the configured size returns
  to its starting value after a second without filling the buffer, or a
  second with a blocked write; queued excess keeps its budget allowance
  as described above. In earlier measurements, four downloads by a
  client 8 ms away on a 4 Gbit/s link, in a 64 MiB cgroup, went from 0.34
  of sing-box's to 0.88-0.91, peaking at 37.8 MiB;
  with 20 clients that stopped reading beside them the peak was 42.2 MiB
  (measured, sail#10). These measurements preceded the queue-accounting
  and readback fixes above. Other profiles leave the buffer to the
  system as before.
